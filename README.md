# 감사 보고서 자동화 시스템

**① 감사처분심의위원회 결과보고서(파일1)** — 감사 팩트를 입력하면 서식 그대로 채워진 `.hwpx`를 만드는 정적 웹앱입니다.
**② 복무감사 결과보고서**는 같은 화면의 두 번째 탭으로 자리를 잡아 두고 준비중입니다.
서버가 없습니다. 입력값·파일은 브라우저 안에서만 처리되고 외부로 나가지 않습니다(실측: 외부 요청 0건).

- 실행: `index.html` 을 열면 끝 (`file://` 동작, 외부 CDN 없음)
- 배포: https://audit-report-chi.vercel.app/ (정적 호스팅)
- 산출물: `감사처분심의위원회_결과보고서_<제목>_<날짜>.hwpx`

## 1. 무엇을 하는가

| 단계 | 입력 | 결과 |
|---|---|---|
| **1. 문서·감사 기본정보** | 심의위원회 회차, 보고일, 제목, 기관·부서, 감사명, 행위 발생일·인지일, 5년 특례, 의결 구분·내용 | 표지·총괄·일람표의 기준값, **징계·문책 시효(3년/5년) D-day** 계산 |
| **2. 건별 처분요구·근거** | 처분요구 1건마다 카드: 제목, 관계부서, 종류·건수·금액·인원, 5단 블록(제목·경위·사실관계·판단/법령·처분요구), 대상자, 근거 담기 | **총괄 집계표 자동 합산**, 담은 근거만 인용, 5블록 누락 체크리스트 |
| **3. 세부 증빙표** *(선택)* | 행 추가/삭제, CSV·엑셀 표 붙여넣기 | `[표] 세부 증빙 내역` (비우면 표 없이 나감) |
| **4. 미리보기·HWPX** | — | A4 웹 미리보기, `.hwpx` 다운로드(브라우저 생성), AI 입력용 텍스트 복사 |

건이 여러 개면 붙임1이 **붙임 1-1, 1-2**로 나뉘고 총괄표·일람표·지적사항 요약이 자동 합산됩니다.

## 2. 서식은 어디서 왔나

원본 **파일1 복구본**(`감사처분심의위원회_결과보고서_masked_repair.hwpx`, 문단 1,203 · 표 19 · 셀 981)을 직접 파싱해
**클린 마스터 템플릿**(`assets/master-template.hwpx`, 53문단 · 8표)을 만들었습니다.

- 원본의 개체(`hp:p`, `hp:run`, `charPrIDRef`, `paraPrIDRef`, `hp:tbl`, `hp:tc`, `cellSpan`, 여백)를 **그대로 재사용**하고 텍스트만 토큰으로 바꿨습니다.
- 사건 실명·개인정보가 담긴 문단은 지우고, 표는 **머리행 + 반복용 1행**만 남겼습니다.
- `Preview/PrvText.txt`(원문 미리보기 텍스트)도 안내문으로 교체했습니다.
- 생성 스크립트: `build/build_master.py` (원본 경로만 바꾸면 재생성 가능)

### 표 매핑
| 서식 표 | 템플릿 | 채우는 값 |
|---|---|---|
| 표지 제목 상자 | 1행×1열 | 회차 + 제목 |
| 1. 총괄(표2) | 3행×12열 | 건수·인원·금액 자동 합산 (`n(값)` 형식) |
| 2. 일람표 | 2행×5열 → 행 복제 | 연번·부서·종류·제목·금액(인원) |
| 3. 지적사항 요약 | 2행×3열 → 행 복제 | 소속·대상자·주요 지적사항 |
| 붙임1 라벨 | 1행×3열 | `붙임 1[-n]` · `감사결과 처분요구 (제목)` |
| 처분요구서 본문 | 문단(paraPr 50/35/53) | 5단 블록 + 담은 근거 인용 |
| 세부 증빙표 | 2행×6열 → 행 복제 | 일자·증빙 항목·내용·금액·비고 |
| [관련자] 명단 | 2행×6열 → 행 복제 | 소속·직급·성명·직무·담당기간·처분요구 |
| 붙임2 관련근거 | 문단 복제 | 담은 근거 목록 |

바인딩 엔진은 `assets/hwpx-writer.js` 입니다. 토큰 `{{NAME}}`(값)과 `{{R:GROUP.FIELD}}`(반복 행·문단)만 처리하고,
반복 행은 `hp:tr` 복제 → `cellAddr`·`rowCnt`·표 높이 재계산, 빈 그룹이면 행·표·문단을 제거합니다.
결과는 JSZip으로 다시 포장하며 `mimetype` 은 **첫 엔트리·무압축**을 지킵니다.

## 3. 지키는 선

- **인용은 담은 근거의 원문 문자열만.** 조문·사건번호를 만들어 넣지 않습니다(담지 않으면 문서에 조문이 생기지 않음 — 실측 확인).
- **양정(징계 종류·정도)은 앱이 정하지 않습니다.** 5블록의 처분요구 문안은 감사인이 씁니다.
- **시효 계산은 참고값.** 중단·정지, 구법·신법 부칙은 감사인 확인 몫으로 화면에 명시합니다.
- **서버 없음.** 입력은 `localStorage`(이 브라우저), 파일은 Blob 다운로드. 외부 요청 0건.
- 사례 DB·규정은 저장본(710건 · 9개 규정 32개 조문)을 정적으로 번들했습니다.
